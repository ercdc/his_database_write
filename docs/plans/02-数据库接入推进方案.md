# HIS 数据首次病程 XML：数据库接入推进方案

## 背景与目标

当前 Demo 已验证以下链路：

```text
HTTP 请求
  → 本地 Fixture HIS 文本
  → DeepSeek Tool Calling
  → XML XSD 校验
  → 本地 Output 文件
```

医院自部署模型 API 暂未取得，模型适配暂时无法推进。下一阶段优先把两端的 Demo 实现替换为数据库适配层：从 HIS 数据库读取数据，并通过数据库函数、存储过程或既有接口回写首次病程。

目标是让链路变为：

```text
HTTP 请求（patientId、visitId）
  → HIS 数据读取适配器
  → Skill + 当前模型客户端
  → XML XSD 校验
  → 首次病程数据库回写适配器
```

本阶段不以医院模型 API 为前置条件；模型服务层仍可继续使用当前已经验证的 DeepSeek 实现。

## 已确认的数据库信息

| 项目 | 当前结论 |
|---|---|
| HIS 数据库 | Oracle |
| .NET 数据访问驱动 | 优先使用 `Oracle.ManagedDataAccess.Core`（ODP.NET 托管驱动） |
| 开发机是否需要安装 Oracle Server | 不需要；应用连接医院提供的开发/测试 Oracle 实例即可。 |
| 开发机是否需要安装完整 Oracle Client | 通常不需要；托管驱动不依赖完整 Oracle Client。 |

Oracle 连接信息应通过环境变量或部署配置提供，不写入源码、`appsettings.json` 或 Markdown 文档。例如生产环境需要由院方提供：主机/IP、端口、Service Name 或 TNS 别名、测试账号和密码。

## 本地 Oracle Demo 验证结果（2026-08-14）

已使用 Docker Oracle Free 完成数据库闭环验证：

```text
POST /api/first-course/generate
  → Oracle 查询 HIS_ENCOUNTER / HIS_MEDICAL_ORDER / HIS_CHARGE / HIS_REPORT
  → DeepSeek 生成 XML
  → XSD 校验
  → PKG_FIRST_COURSE.UPSERT_RECORD
  → FIRST_COURSE_RECORD.RECORD_XML
```

验证结果：`CASE-001 / TEST20260811001` 的请求成功返回 `oracle://FIRST_COURSE_RECORD/CASE-001/TEST20260811001`，数据库已保存 XML。该 Oracle 实例和表结构仅用于本地脱敏 Demo，不代表医院真实 HIS 结构。

## 设计原则

1. 模型不直接连接或操作数据库。模型仅生成 XML；C# 在模型外完成 XML 校验和数据库读写。
2. HIS 数据读取和首次病程回写均通过接口抽象，保留本地 Fixture/文件写入实现，避免失去脱离医院环境的测试能力。
3. 数据库适配仅替换底层实现，不改变 `FirstCourseSkill`、工具声明、`ToolRegistry` 或通用模型调用协议。
4. 回写前必须通过 `Resources/Skills/FirstCourse/schema.xsd`；数据库写入失败不能被伪装为模型生成成功。

## 推荐分层

```text
Controller
  ↓
FirstCourseGenerationService
  ├─ IHisEncounterDataProvider
  │    ├─ FixtureHisEncounterDataProvider       # Demo：读取文本文件
  │    └─ DatabaseHisEncounterDataProvider      # 生产：查询 HIS
  │
  ├─ IToolCallingModelClient
  │    └─ DeepSeekToolCallingClient             # 当前可替换模型客户端
  │
  └─ write_first_course_xml
       ↓
     IFirstCourseRecordWriter
       ├─ LocalFirstCourseRecordWriter           # Demo：写 Output/*.xml
       └─ DatabaseFirstCourseRecordWriter        # 生产：调用 HIS 回写函数/存储过程
```

说明：`XmlRecordWriter` 应继续保留为通用基础能力，负责 XML 解析与 XSD 校验；生产回写实现调用它完成校验后，再调用 HIS 既有回写能力。

## HIS 数据读取

生产读取接口建议表达为：

```csharp
public interface IHisEncounterDataProvider
{
    Task<string> GetRawDataAsync(
        string patientId,
        string visitId,
        CancellationToken cancellationToken);
}
```

返回值仍然保持原始多段文本的拼接形态，不在这一层做医学总结或模型预处理：

```text
【病案】
...

【医嘱】
...

【费用】
...

【报告】
...
```

这既符合当前 Demo 的输入，也能让未来数据库 SQL 或医院既有查询函数替换实现，而不影响提示词和 Skill。

## 首次病程回写

生产回写接口建议表达为：

```csharp
public interface IFirstCourseRecordWriter
{
    Task<RecordWriteResult> WriteAsync(
        string xml,
        ToolExecutionContext context,
        CancellationToken cancellationToken);
}
```

推荐处理顺序：

```text
模型工具参数 xml
  → XmlRecordWriter / XSD 校验
  → 调用医院提供的函数、存储过程或回写接口
  → 返回真实写入结果
```

不建议把模型生成的 XML 直接交给数据库函数。XSD 校验必须位于数据库调用之前。

## 接入数据库前必须确认的事实

### HIS 读取侧

1. 可用的开发/测试 Oracle 数据库地址、端口、Service Name 或 TNS 别名。
2. 连接数据库所需网络条件：院内网络、VPN、IP 白名单、防火墙端口。
3. 可用于开发测试的 Oracle 账号、密码，以及该账号的只读对象权限。
4. 项目使用 `Oracle.ManagedDataAccess.Core` 作为 .NET 托管驱动；除非院方明确要求 OCI/非托管驱动，否则不安装完整 Oracle Client。
5. 病案、医嘱、费用、报告对应的现有查询函数、存储过程或 SQL。
6. 输入参数是否确实是 `patientId`、`visitId`，以及它们的数据类型和命名。
7. 一组允许测试的脱敏患者与就诊数据。
8. 查询结果的字段名、时间格式、空值表达和最大数据量。

### 首次病程回写侧

1. 可用于开发测试的 Oracle 写入账号，以及目标包、存储过程、函数或表的执行/写入权限。
2. 回写使用数据库函数、存储过程、表写入还是 HIS 内部接口。
3. 回写接收 XML、JSON 还是字段对象；若不是 XML，需要明确 XML 到入参的转换责任。
4. 成功、业务失败、系统失败时的返回码与错误信息。
5. 同一患者同一就诊已存在首次病程时，是拒绝、覆盖还是更新版本。
6. 主记录和诊断、辅助检查、诊疗计划等子数据是否要求同一 Oracle 事务。

## 当前明确不做的内容

- 不直接连接生产 HIS 数据库；只允许使用开发/测试环境。
- 不猜测 SQL、表结构、存储过程名称或回写规则。
- 不修改模型 Prompt 来代替数据库层业务规则。
- 不在此阶段接入医院自部署模型；该问题继续记录在 `../design/设计信息记录.md`。

## 验收标准

数据库适配完成后，需要证明：

1. `CASE-001` 等测试标识可由数据库读取适配器获取四段 HIS 原始数据。
2. 生成 XML 仍通过当前 XSD。
3. 回写适配器返回数据库的真实成功结果与记录标识（如果院方接口提供）。
4. 数据库写入失败时 HTTP 接口返回失败，不产生“成功写入”的假响应。
5. Fixture 模式和本地 Output 模式仍保留，并能通过自动测试。
