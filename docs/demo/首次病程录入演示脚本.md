# 首次病程录入 Demo 演示脚本

本脚本用于演示完整链路：Apifox 发起请求，服务从 Oracle 获取 HIS 数据，调用 DeepSeek 生成 XML，并把首次病程写回 Oracle。

本地数据均为脱敏 Demo 数据，不代表真实病历或临床结论。

## 一、演示前准备

### 1. 启动 Oracle

在项目根目录执行：

```powershell
docker compose -f .\docker-compose.oracle-demo.yml up -d
```

### 2. 以 Oracle 模式启动服务

另开一个 PowerShell 窗口，在项目根目录执行：

```powershell
$env:DEEPSEEK_API_KEY = "你的 DeepSeek API Key"
$env:Database__Mode = "Oracle"
$env:Database__OracleConnectionString = "User Id=HIS_DEMO;Password=HisDemo_2026;Data Source=localhost:1521/FREEPDB1"

dotnet run --project .\src\HisMedicalRecordFillDemo\HisMedicalRecordFillDemo.csproj --urls "http://127.0.0.1:5088"
```

确认终端出现：

```text
Now listening on: http://127.0.0.1:5088
```

### 3. 打开工具

- 打开 Apifox，进入 `POST /api/first-course/generate` 的已有测试用例 `case01`。
- 打开 Navicat，并连接本地 Oracle Demo 数据库；本次仅手动执行下文 SQL 查看数据。

## 二、演示开始前：展示 HIS 数据已存在、首次病程尚未录入

在 Navicat 执行以下 SQL，展示两名 Demo 患者的病案数据已存在：

```sql
SELECT
    PATIENT_ID,
    VISIT_ID,
    PATIENT_NAME,
    GENDER,
    AGE,
    WARD_NAME,
    ADMITTED_AT
FROM HIS_ENCOUNTER
WHERE (PATIENT_ID = 'CASE-001' AND VISIT_ID = 'TEST20260811001')
   OR (PATIENT_ID = 'CASE-002' AND VISIT_ID = 'TEST20260812002')
ORDER BY PATIENT_ID;
```

然后确认首次病程表中还没有这两条记录：

```sql
SELECT
    PATIENT_ID,
    VISIT_ID,
    CREATED_AT,
    UPDATED_AT
FROM FIRST_COURSE_RECORD
WHERE (PATIENT_ID = 'CASE-001' AND VISIT_ID = 'TEST20260811001')
   OR (PATIENT_ID = 'CASE-002' AND VISIT_ID = 'TEST20260812002')
ORDER BY PATIENT_ID;
```

预期结果：无记录。

## 三、在 Apifox 录入第一名患者的首次病程

在已有的 `case01` 用例中，将 Body 设置为：

```json
{
  "patientId": "CASE-001",
  "visitId": "TEST20260811001"
}
```

点击“运行”。

演示时说明：服务根据患者与就诊 ID 查询 Oracle 中的病案、医嘱、费用和报告；随后读取首次病程技能资源，调用 DeepSeek，并通过工具调用写回 XML。

预期 HTTP 响应：

```json
{
  "success": true,
  "outputPath": "oracle://FIRST_COURSE_RECORD/CASE-001/TEST20260811001",
  "message": "..."
}
```

其中 `message` 的文本由模型在工具执行完成后返回，因此每次内容可能不同。

## 四、在 Navicat 展示 XML 已写回 Oracle

在 Navicat 执行：

```sql
SELECT
    PATIENT_ID,
    VISIT_ID,
    CREATED_AT,
    UPDATED_AT,
    DBMS_LOB.SUBSTR(RECORD_XML, 2000, 1) AS RECORD_XML_PREVIEW
FROM FIRST_COURSE_RECORD
WHERE PATIENT_ID = 'CASE-001'
  AND VISIT_ID = 'TEST20260811001';
```

演示重点：查询结果从“无记录”变为一条记录，且 `RECORD_XML_PREVIEW` 可看到生成的 XML。

## 五、复用同一个 Apifox 用例演示第二名患者

不新增 Apifox 用例，只将 `case01` 的 Body 改为：

```json
{
  "patientId": "CASE-002",
  "visitId": "TEST20260812002"
}
```

点击“运行”，成功响应中的路径应为：

```text
oracle://FIRST_COURSE_RECORD/CASE-002/TEST20260812002
```

回到 Navicat 执行：

```sql
SELECT
    PATIENT_ID,
    VISIT_ID,
    CREATED_AT,
    UPDATED_AT,
    DBMS_LOB.SUBSTR(RECORD_XML, 2000, 1) AS RECORD_XML_PREVIEW
FROM FIRST_COURSE_RECORD
WHERE PATIENT_ID = 'CASE-002'
  AND VISIT_ID = 'TEST20260812002';
```

预期结果：二号患者也新增一条 XML 首次病程记录。

## 六、演示结束时的总结话术

> 该 Demo 对外只暴露一个首次病程生成接口。调用方只需要传入患者 ID 和就诊 ID；服务内部完成 HIS 数据读取、提示词与 XML 模板加载、DeepSeek Tool Calling、XML 校验和 Oracle 回写。当前 Oracle 表结构与病例数据均为本地脱敏演示数据。
